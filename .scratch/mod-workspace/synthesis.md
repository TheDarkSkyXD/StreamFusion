# Workspace design decision

Candidate A scored 26/30 and Candidate B 25/30 in independent review. Choose A's binary split tree and stable flat widget hosts. Twitch's tested edge insertion rules require arbitrary nested splits; B's three templates cannot represent them.

Take B's derived hidden tray, normalized persistence boundary, narrow-window stack, and explicit keyboard move menu. Use split paths instead of persisted generated IDs. Keep video and chat visible. Optional moderation tools can be hidden and restored.

Native HTML5 dragging did not start reliably in Electron. Replace it with pointer capture on the stable canvas; capturing a hidden source header was also unreliable. Flat keyed hosts preserve live component identity across tree changes. Commit local storage only after an interaction finishes.

The user narrowed docking after trying it. Pin AutoMod on Twitch and Retention on Kick. Mod Actions only moves beside that anchor. Add outer-edge docking so chat can span the entire right side. Keep the tree because it still represents resizable nested panels; enforce the user's placement rules before accepting a drop and when restoring old layouts. Use green focus/drop indicators for Kick.

The access flash came from a scope effect depending on the whole authority object. A chat role snapshot recreated that object, restarting validation and unmounting chat. Depend on semantic authority state and scope identity instead. The regression fails against a73b2a8 in C:/sf-perf-commit: expected one tokenStatus call, got two. Owners may now open their resolved workspace while individual remote tool permissions are checked.

Throughput checkpoint: parallel ownership is the pure layout engine, live adapters, and parent-owned workspace integration. Gate each with focused tests, then one real Electron pass, independent review, and the compiled smoke gate before committing to main.
